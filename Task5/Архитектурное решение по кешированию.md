# 1. Объекты кеширования
- список  заказов для операторов
- стоимость обработанных изделий
- данные клиентов


# 2. Мотивация
- снижение нагрузки на базу данных 
- стабилизация при увеличении заказов
- улучшение впечатления пользователей за счет быстродействия системы

# 3. Предлагаемое решение 

## Выбираем cache-aside
- больше всего нагружены MES, CRM и БД
- при наличии данных в кеше данные будут отданы из него, при отсутствии - из БД и закешируются для новых запросов

## Почему не другие паттерны
### Refresh-ahead 
не подходит для систем с динамичным измением данных, таких как заказы
### Write-Through н
е подходит из-за редкости записи

# 4. Стратегия инвалидации кеша 

## По ключу
Плюсы:
- легко реализовать
- прямое изменение данных
- соответствие между изменениями данных и обновлением кеша

Минусы:
- необходимо отслеживать измененных данных
- возможная сложность управления маппингом

## Программная
Плюсы:
- высокий уровень контроля 
- адаптивность для сложной логики

Минусы:
- возможные ошибки 
- сложность в реализации и поддержке


## По времени
Плюсы:
- легко реализовать
- подходит для данных, которые обновляются часто или с заданной периодичностью

Минусы:
- возможное устаревание кеша до инвалидации

Выбираем по стратегию инвалидации по ключу, так как она обеспечивает прямое управление кешем
