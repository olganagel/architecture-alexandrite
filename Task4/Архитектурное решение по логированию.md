# 1. Необходимые логи

## INFO
- изменение статуса заказа (номер заказа, статус, дата и время, id клиента)
- загрузка файлов в хранилище (номер заказа, дата и время загрузки файла, наименование и вес)
- осуществление запросов к базе данных (запрос, дата и время)



## ERROR
Уровень необходим для поиска ошибок 
- ошибки оправки запросов 
- таймаут операций в базе данных


# 2. Мотивация

- оперативное обнаружение проблем для понимания, что чинить, а также ранее предотварещение проблем
- отслеживание слабых мест системы 
- повышение надежности: быстрое выявление и диагностика ошибок, инцидентов и нестабильного поведения сервисов.

Обеспечить логированием необходимо самые нагруженные элементы системы:
- MES 
- CRM

## Политика безопасности логов
- Не логировать чувствительные данные 
- Ограничение доступа к УЗ только для бекэнд разработчиков (выделение сетевого прохода)
- Аутенификация по доменной УЗ при наличии нужного прохода
  
## Политика хранения логов
- Глубина хранения - 10 дней
- Планируемый размер - 50 Мб в сутки для каждого сервиса

# 4. Мероприятия для превращения системы сбора логов в систему анализа логов

## Алерты
- при превышении установленного лимита ошибок в сервисе 
- при отсутствии логов за установленное время
- при аномальном увеличении заказов за короткое время
  
## Унификация  
Каждый сервис должен вести логи в едином формате
