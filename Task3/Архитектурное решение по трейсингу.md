# 1. Анализ для внедрения трейсинга
## Места потери заказов

- MES: большая нагрузка при оценке заказа
- CRM: все предоставляемые API должны передавать заказы в CRM
- RabbitMQ: разрастающаяся очередь может вести к потере давно ожидющих сообщений 

## Данные

- Имя сервиса
- Имя операции
- Статус операции
- Дата и время старта операции
- Дата и время завершения операции
- Ошибки
- Идентификатор трейса

# 2. Мотивация

## Плюсы от внедрения трейсинга

- оперативное обнаружение проблем для понимания, что чинить, а также ранее предотвращение проблем
- отслеживание слабых мест системы


## Бизнес-метрики, на которые повлияет внедрение трейсинга:

- DAU
- MAU
- Retention

# 4. Компромиссы

- Большие затраты времени и финансов на обучение команды новому стеку
- Затраты на новое железо, так как для трейсинг ест память
- Вероятная несовместимость кодовой базы системы с OpenTelemetry 

# 5. Аспекты безопасности

- Ограничение доступа к УЗ только для бекэнд разработчиков (выделение сетевого прохода)
- Аутенификация по доменной УЗ при наличии нужного прохода
- Обучение команды в части разрешенных к логированию данных
