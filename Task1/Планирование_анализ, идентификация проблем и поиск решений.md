# I. Проблемы компании

1. Недовольство клиентов из-за ожидания заказов
2. Потеря прибыли из-за потерянных заказов 
3. Ухудшение позиции компании на рынке и потеря крупных заказов и потенциальных партнеров
4. Торможение работы операторов из-за долгой прогрузки системы и потеря вознаграждения за взятие заказа
5. Задержки релизов растут,как снежный ком
6. Непонимание команды разработки причин проблем и соответственно отсутствие их решения
7. Маленькая команда и недостаток экспертизы

# II. Пути решения в порядке приоритета

## 1. Внедрение паттернов снижения нагрузки
### Backpressure в MES
Для контроля потока данных из CRM: при большой нагрузке сообщаем MES о необходимости подождать, чтобы не заставлять ждать клиентов и не терять прибыль и заказы

### Circuit Breaker в CRM
Если не получаем ответ от MES в обозначенное количество запросов, то временно перестаем тратить ресурсы и пробуем снова через установленный период для проверки, ожил ли MES

### Кеширование
Для снижения нагрузки на базу данных сохраняем с помощью Redis данные заказов, чтобы операторам меньше ждать получения данных страницы MES

Пункты выбраны как лучшие практики для решения проблем

## 2. Повышение наблюдаемости системы
Настройка мониторинга, логирования и трейсинга. Метрики подскажут слабые места системы


## 3. Проработка команды

### Разработчики
Держатели знаний основного стека (C#, React) не должны быть в единственном экземпляре. При временном уходе одного из разработчиков простои увеличиваются, подхватить некому, а при увольнии и подавно

### Тестировщики
Вряд ли один тестировщик в ручную справляется с проверкой всех кейсов. Необходим найм или обучение автотестированию одного из тестировщиков
